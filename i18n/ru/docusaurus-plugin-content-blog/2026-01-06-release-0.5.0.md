0.5.0 обновляет gorizond-cluster, и мы выкатили его через полный GitOps-стек. Ниже также подробно про то, как `fleet-gitops` разворачивает всю платформу.

<!-- truncate -->

### Что изменилось в gorizond-cluster 0.5.0
- Перевели Fleet deployment на HelmOp для headscale/k3s с автоматическим созданием namespace.
- Ужесточили обработку имён downstream-ресурсов до DNS-1123 (<=63 символов), чтобы избежать невалидных имён в Rancher.
- Добавили валидацию имён кластеров gorizond, чтобы блокировать некорректный provisioning заранее.

Полные заметки: [v0.5.0](https://github.com/gorizond/gorizond-cluster/releases/tag/v0.5.0); diff [v0.4.2...v0.5.0](https://github.com/gorizond/gorizond-cluster/compare/v0.4.2...v0.5.0).

### Совместимость и уборка старых кластеров
- 0.5.0 обратно совместим с кластерами, развернутыми через 0.4.x.
- Формат очистки headscale/k3s изменился: вместо Fleet Bundle теперь используется HelmOp.
- При удалении старых кластеров нужно вручную очистить legacy Fleet Bundle. В идеале лучше полностью заменить старые кластера, чтобы избежать смешанных путей очистки.

### GitOps-основа: fleet-gitops
Мы используем [fleet-gitops](https://github.com/gorizond/fleet-gitops) как bootstrap-репозиторий для Fleet. Это Helm-чарт, который из `values.yaml` генерирует Fleet ресурсы `GitRepo` и `HelmOp`, поэтому один репозиторий становится источником правды для всего: от runtime-кластера до core-сервисов и баз данных.

Как он устроен сейчас:
- `fleet-local` репозитории для platform control plane: `fleet-gorizond-cluster` (контроллер gorizond-cluster + чарты), `fleet-workspace-controller`, `fleet-cert-manager`, `yookassa-url-generator`, `docusaurus`, `jspolicy-for-autoscaler`, `fleet-clusters`.
- `fleet-default` репозитории для shared runtime: `fleet-cert-manager` и `fleet-gorizond-database`.
- HelmOps для инфраструктурных чартов, таких как `jspolicy` и `longhorn`.

Операционные детали, на которые опираемся:
- Таргетинг кластеров по лейблам вида `<name>=enabled`, плюс опциональные cluster selectors/groups.
- `paths` позволяет таргетить конкретные поддиректории (например, чарты или policies).
- В сгенерированных Fleet ресурсах включена корректировка дрейфа (drift correction).

### Как обновиться
- В вашем GitOps/Fleet bundle установите `chartVersion` для `gorizond-cluster-controller` на `0.5.0` (tag `v0.5.0`).
- Если инфраструктура управляется через `fleet-gitops`, обновите там значения bundle для контроллера и дождитесь reconcile.
- Выложите через Fleet/Helm и дождитесь `Ready` у `BundleDeployment` и перезапуска pod контроллера.

### Как проверить
- Новые namespace для headscale/k3s создаются автоматически HelmOp при создании кластера.
- Создание кластера с некорректным именем отклоняется до provisioning.
- В логах контроллера чистый reconcile, а Rancher-ресурсы имеют DNS-1123-safe имена.
